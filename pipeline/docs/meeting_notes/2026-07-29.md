## 3. Jasmine's design — K-fold stacked model

Directly transferred from her NWS lab work. The core idea:

1. **Base model (built now):** Random Forest on wind-direction ×
   pollutant-flow × meteorology → pollutant-concentration prediction
   at each of the Coastal-Bend sites.
2. **Second stack (built later, when BREATHE-CC data lands):** takes
   the base model's predictions as input, targets health-outcome
   incidence at residential-zone × time resolution. Whoever inherits
   the project *"wouldn't even have to build the entire framework
   because 75% of it would already be done."*
3. **K-fold protection against data leakage.** Data split into 3
   folds; base model trains on 2, holds out the third; second stack
   trains on that third fold to guarantee no test-set contamination.

**Why this matters for methodological defensibility.** XGBoost is
"very, very prone to overfitting" (Jasmine's phrase), and even Random
Forest can leak. Jasmine's own project revealed this the hard way. The
K-fold scaffold means the team can defend the model against reviewers
who accuse of over-good performance being data leakage.

**Model choice for the base:** Random Forest. Dr. Melaram: *"That's
what I said. One is always the best."* Deliberate rejection of the
model-shopping tendency ("compare 5 models") that adds noise without
value. Start with one, expand only if performance is unacceptable.
